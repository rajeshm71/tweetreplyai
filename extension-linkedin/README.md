# LinkedIn Reply AI — Browser Extension

Generate authentic, professional replies to LinkedIn posts and comments using AI. This extension adds a **Generate Reply** button next to LinkedIn comment boxes and uses the TweetReply AI backend to produce context-aware replies.

## Prerequisites

- **Node.js** and **npm** (for building)
- **Chrome** (or a Chromium-based browser that supports Manifest V3 extensions)

## Build

From the project root:

```bash
npm run build:linkedin
```

This produces:

- `content/linkedin-content.bundle.js`
- `popup/popup.bundle.js`
- `background/background.bundle.js`

Icons are generated once via:

```bash
node scripts/gen-linkedin-icons.js
```

(Icons are already checked in under `icons/`.)

## Load the extension

1. Open Chrome and go to `chrome://extensions`.
2. Turn on **Developer mode** (top right).
3. Click **Load unpacked**.
4. Select the `extension-linkedin` folder (the one containing `manifest.json`).

The extension icon should appear in the toolbar. No icon errors should appear on the extensions page.

## Usage

1. **Sign in**  
   Click the extension icon and choose **Sign In**. A tab opens to the TweetReply AI web app. Log in there; the extension will sync your session and show your name, plan, and credit usage in the popup.

2. **Reply style**  
   In the popup, open **Settings** and set **Default Tone** (Default, Professional, Insightful, Conversational, Supportive, Direct). The choice is saved and used for all generated replies until you change it.

3. **Generate replies on LinkedIn**  
   Go to [LinkedIn Feed](https://www.linkedin.com/feed/), open any post, and focus the main comment box or a reply box. A **Generate Reply** button appears next to the submit control. Click it to generate a reply; the text is inserted into the comment field. You can edit it before posting.

4. **Your own posts**  
   When you reply to a comment on your own post, the extension detects that you are the post author and the backend uses the matching “post author” reply style.

## Manual verification checklist

After loading the extension, you can confirm behaviour with this checklist:

- **Auth and popup**  
  - Sign In opens the web app; after login, popup shows authenticated state (name, plan, credits).  
  - Changing Default Tone in Settings persists after closing and reopening the popup.  
  - Logout shows Sign In again; content script shows “Sign in required” when not authenticated.

- **Content script**  
  - On a feed post’s main comment box, “Generate Reply” appears; clicking it inserts a reply.  
  - Same for a reply-to-comment box; generation works and the server receives thread context.  
  - On your own post, “Generate Reply” works and uses the post-author style.

- **Errors**  
  - No auth: “Sign in required”.  
  - Quota exceeded: “Quota exceeded”.  
  - After 401 (e.g. expired token): re-login from popup; content script shows “Sign in required” until re-authenticated.

## Optional: Custom API domain

By default the extension uses `tweetreplyai.vercel.app`. To point it at a different backend (e.g. localhost), you would add a setting that stores `apiDomain` and have the extension use it when calling the API (background script and API client). This is not implemented in the current version.

## Store listing (if publishing)

When submitting to the Chrome Web Store (or similar):

- **Screenshots**: Popup (authenticated), “Generate Reply” on a LinkedIn post, and optionally the Settings panel.
- **Description**: Short feature list and that replies are generated by the TweetReply AI service.
- **Privacy policy**: Publish a policy and link it in the listing. Ensure it covers:
  - Data sent to your backend (post/comment text, auth token).
  - `host_permissions`: `https://www.linkedin.com/*`, `https://tweetreplyai.vercel.app/*`, and `http://localhost:*/*` if you document local development.

## Structure

- **content/** — Injected into LinkedIn pages; finds comment boxes, extracts post/thread context, calls API, inserts reply.
- **popup/** — Sign in/out, usage, plan, Default Tone setting.
- **background/** — Service worker; auth sync from web app, API proxy, install welcome.
- **utils/** — API client (adds `platform: 'linkedin'`), auth manager.
- **config/** — API domain, timeouts, validation limits.
